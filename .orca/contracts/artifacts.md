# Pipeline file and artifact contracts

Use `<ticket_name>` as the ticket filename without `.md`, stable work-unit IDs
from the plan, and filesystem-safe run names. Every created or modified file must
have an owner, appear in a report, and use a path that cannot collide with a
parallel work unit.

## File classes and permitted locations

### Repository deliverables

These are permanent outputs intended to remain after PASS:

- Implementer-created or modified production code, configuration, and
  documentation at the exact paths authorized by the plan.
- Evaluator-created acceptance/regression tests under `tests/`.

The implementer must not modify evaluator-owned tests merely to force PASS. The
evaluator must not modify production code or configuration.

### Pipeline records

Store durable coordination and evidence records under:

```text
artifacts/<ticket_name>/
```

Permitted files include:

- `plan.md`
- `implement_<unit_id>_<attempt>.md`
- `evaluate_<attempt>.md`
- evaluator diagnostic scripts, extracted evidence, plots, and comparison tables
  whose names identify their purpose and attempt

Do not put import-dependent training script copies here. Temporary files that are
not useful evidence should be deleted before reporting; retained diagnostics
must be listed in the evaluation report.

### Experiment launch and runtime artifacts

Each experiment work unit may create:

- `train_ppo_gomoku_<run_name>.py` in the repository root — the unit's unique,
  reproducible launch configuration; never overwrite another unit's copy.
- `logs/<run_name>.log` — redirected process output.
- `mlruns/<experiment_id>/<run_id>/...` — MLflow-generated parameters, metrics,
  tags, metadata, and artifacts.
- Run-specific models/checkpoints under `outputs/` and snapshots under
  `self_play_snapshots/`, using names that do not collide with other runs.
- Other files generated by the existing trainer only when their paths are
  recorded in the implementation report.

Training processes, not workers or evaluators, generate MLflow/model artifacts.
Never hand-edit them. Keep the launch script, log, MLflow run, and referenced
checkpoints through evaluation. The final report must state whether the root-level
launch script is retained for reproducibility or is safe to remove after the run.

### Scratch files

Use `artifacts/<ticket_name>/tmp/` for ticket-local scratch data. Do not leave
scratch scripts in the repository root, `tests/`, or source directories. Remove
the `tmp/` contents before PASS unless a file is promoted to named evaluation
evidence and listed in the report.

## Planner artifact

Write `artifacts/<ticket_name>/plan.md`:

```markdown
## Goal
## Type
## Acceptance criteria
## Plan
## Work units
- id: <stable-id>
  independent: yes|no
  inputs/dependencies: ...
  files read: ...
  files created or modified: ...
  runtime artifacts: ...
## Risks and assumptions
## Done when
```

For code units, enumerate exact writable repository paths. For experiment units,
name the root-level script copy, log path pattern, run name, and expected model /
snapshot destinations. Two units are independent only when all writable paths
and runtime names are disjoint.

## Implementer artifact

Write `artifacts/<ticket_name>/implement_<unit_id>_<attempt>.md`:

```markdown
## Completed
## Files created
- <path> — <purpose; permanent|runtime|temporary>
## Files modified
- <path> — <change>
## Runtime artifacts and processes
- <run ID/PID/log/model/snapshot paths, or none>
## Verification done
## Cleanup / outstanding files
## Notes / handoff
```

List files even when they are gitignored. `git diff` is not a substitute because
it omits logs, MLflow runs, models, snapshots, and other runtime output. Report
unexpected partial files and failed-launch artifacts rather than silently leaving
them behind.

For experiments, the handoff must include run name, immutable run ID/path when
known, baseline run ID, PID, log path, launch time, launch script, exact
configuration difference, known model/snapshot destinations, and first suggested
recheck time.

## Evaluator artifact

Write `artifacts/<ticket_name>/evaluate_<attempt>.md`:

```markdown
## Evidence
## Files created
- <test, diagnostic, plot, table, or none>
## Files modified
- <test path and reason, or none>
## Runtime artifacts inspected
- <run/log/model/metric paths, or none>
## Cleanup / retained evidence
## Assessment
## Verdict
VERDICT: PASS|FAIL|HOLD
FEEDBACK: <blank for PASS; actionable correction or missing evidence otherwise>
```

Evaluator-created permanent tests belong under `tests/`; temporary diagnostics
belong under the ticket artifact directory. The evaluator lists, but never
modifies, experiment runtime artifacts. On retries, update an existing stable
acceptance-test file when appropriate rather than creating duplicate attempt
files.

The `VERDICT:` and `FEEDBACK:` lines must be the final two lines. HOLD is valid
only for experiment tickets.

## Orca completion message

The final `worker_done --files-modified` field must list every file directly
created or changed by that worker, including report files and evaluator tests.
Generated runtime trees that are too large to enumerate belong in the report and
`worker_done` body as concise root paths plus run ID. An empty file list is valid
only when the report explicitly confirms that no files were created or modified.
